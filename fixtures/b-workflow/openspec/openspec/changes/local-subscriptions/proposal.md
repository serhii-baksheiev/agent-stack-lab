## Why

The synthetic subscription card needs a predictable domain transition so repeated submissions cannot create duplicate local records. The common feature brief is the authorized product input; this is a manual-load Codex trial, with no native Claude session.

## What Changes

Accept normalized lab-format email, reuse existing subscriptions, allocate deterministic IDs, and return immutable state transitions. Persisting JSON remains the caller's responsibility. Invalid submissions raise TypeError.

## Capabilities

### New Capabilities
- `local-subscriptions`: Duplicate-safe subscriptions with caller-owned serializable state.

### Modified Capabilities
None.

## Impact

New `src/subscriptions.mjs` and dependency-free Node tests. The synthetic visual fixture's email and confirmation needs inform the boundary; no UI or real Figma integration is implemented. No backend, network or package dependency is introduced.
