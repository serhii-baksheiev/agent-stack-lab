# Official reference memory and native memory

`node scripts/spike-e-reference-memory.mjs` runs the bounded experiment from the lab root. It pins npm `@modelcontextprotocol/server-memory@2026.8.31`, gitHead `a40bc270fb5ece62673f8a1196f57116d885c5eb`, verifies SHA512 and records the dependency lock, source hash, upstream activity and raw MCP responses. All packages, native profiles and live storage use unique ignored `.lab-runs/e-reference-*` paths. No inference or personal memory was accessed. The optional native registration probe uses existing pinned `.lab-runs/f-tools` Codex 0.154.0 / Claude Code 2.1.270; missing binaries produce an explicit unverified result.

## Reference server findings

The published package exposes nine graph CRUD/search tools through actual stdio MCP. Its handshake identifies `memory-server` version `0.6.3`, not the package release `2026.8.31`; protocol negotiation alone cannot prove the installed package pin. Package/source hashes remain necessary. The pinned source uses a package-relative default `memory.jsonl`; relative configured paths are also package-relative. Each request reloads the graph and mutating operations rewrite it via a temporary file and rename. There is no transaction lock spanning read-modify-write.

The local Windows trial showed exact fresh-process retrieval and export/import replay, and repeated entity creation added no new entities. Four literal corpus queries returned expected names, precision/recall 1 each, at 136–1,175 response bytes. This tiny substring-retrieval corpus does not establish semantic retrieval quality or model-token efficiency. A synthetic canary was stored and returned verbatim: the server supplies no secret filter.

Separate explicit absolute files isolate data operationally. Pointing project B at project A's path exposes A's graph; using the package default from different working directories also shares data. This is path selection, not project authorization. Different checkouts intentionally sharing an absolute file do see the same graph.

Corrupt JSONL caused reads and writes to return tool errors; failed writes preserved the corrupt bytes. Restoring a previously copied good file recovered the exact graph. This is explicit backup restoration, not automatic corruption repair. Deleting an entity removed its incident relations and left other entities. A graph exported by `read_graph` was imported by replaying `create_entities` and `create_relations`; no dedicated import/export command is claimed.

Four local concurrent rounds attempted 24 writes each from two independent servers. Successful acknowledgements were 22/18/21/22, persisted entities 17/12/14/14, and acknowledged names missing afterward 5/6/7/8. Other writes returned Windows filesystem errors. The first summary incorrectly subtracted persisted from attempts; it was corrected from the preserved raw response names without rerunning. The current collector counts missing acknowledged names directly. These observations disqualify this reference implementation as a shared concurrent-write authority. Atomic replacement reduces torn-file exposure but does not prevent lost updates. Hosted results may have different error/loss counts and must be reported separately.

Package removal preserves an explicitly configured external data file but removes default data inside the package directory. Unregistering MCP is not equivalent to deleting data; deleting the package is not a safe data-retention policy for its default path. No network calls appear in the server source and protocol calls use local stdio, but this run did not enforce OS network isolation. Power-loss durability and cross-version data migration remain unverified.

## Native capabilities from current official documentation

Codex uses a separate local memory store under `CODEX_HOME`, normally `~/.codex/memories`. It derives memories from eligible prior chats in the background; updates are delayed and can skip due to quota. Memories are off by default and have separate generation/use controls; `/memories` changes chat-level participation. Required team guidance belongs in `AGENTS.md` or checked-in docs. The isolated 0.154.0 feature listing independently reports `memories stable false`; extraction/recall was not exercised. [Official local memories documentation](https://learn.chatgpt.com/docs/customization/memories?surface=app).

Codex exposes configurable generation idle time, source age and remaining-rate-limit thresholds. These are recall lifecycle controls, not a shared multi-agent transaction or project-access API. Documentation describes model-based extraction/consolidation; this lab did not spend inference quota to benchmark it. [Official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference).

Claude auto memory is enabled by default and machine-local. Repository worktrees/subdirectories share its memory directory. Its entrypoint loads only the first 200 lines or 25KB; topic files load on demand. The memory directory can be relocated through trusted user/policy settings or explicit settings, not project settings. Markdown can be inspected, edited or deleted; `/memory` exposes controls. These documented behaviors are not proof of actual model recall in this trial. [Official Claude memory documentation](https://code.claude.com/docs/en/memory).

Native memory provides harness-specific recall; the reference MCP provides explicit graph storage. Neither measured surface establishes a cross-harness, authorization-enforced, concurrent-safe project memory service. Keep the reference server as a transparent single-writer baseline or reject it for shared authority; choose any additional memory layer only on measured value over native recall plus project-owned documentation.

## Basic Memory concurrency probe qualification

The first hosted stress attempt (34837744747) stopped at an immediate seed Markdown read with ENOENT. Basic Memory 0.23.2 acknowledges database writes before asynchronous Markdown materialization, so that failure establishes a collector assumption error, not a lost acknowledged note. The revised `scripts/spike-e-basic-concurrency.mjs` checks seed and append content through MCP and polls the Markdown projection for at most 15 seconds per check. It records immediate missing markers, final observations through both independent MCP readers, reader disagreement, and projection timeouts separately. Its `lostAcknowledgedMarkers` field means absent through both readers at that bounded observation; it does not establish permanent loss. Distinct-note controls separately report logical readability and projection convergence. No write queue or backend changes are introduced, and canonical run 34839170081 observed 12/16 acknowledged appends, four structured indexing errors, zero missing acknowledged markers at final reads, zero reader disagreements and zero projection timeouts; all distinct-note controls passed. Markdown alone is a projection backup; full-state recovery needs the quiescent database, Markdown, and configuration.
